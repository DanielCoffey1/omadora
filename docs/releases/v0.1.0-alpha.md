# Omadora v0.1.0-alpha

First public alpha of the independent minimal Omarchy 4 desktop port for
**Fedora Workstation 44, x86_64 (non-Atomic)**.

## Install

```bash
curl -fsSL https://raw.githubusercontent.com/DanielCoffey1/omadora/v0.1.0-alpha/boot.sh | bash
```

Run as your regular user, then log out and choose **Omadora** in GDM.
[Quick start, updates and recovery](https://github.com/DanielCoffey1/omadora/blob/v0.1.0-alpha/docs/QUICKSTART.md).

## Included

- Omarchy 4.0.4's Hyprland/Quickshell desktop, themes, shortcuts, menus,
  notifications and lock screen, with Omadora branding and animated wordmark.
- A minimal base with Foot, Neovim, Firefox and Files. Fedora's existing apps
  are retained. Games, office/media suites and AI agents are optional.
- 93 optional choices with Fedora, RPM Fusion, Flatpak, vendor or managed
  download mappings. AI includes Codex CLI and Claude Code; Gaming includes
  Steam, Lutris and additional launchers/tools. Coverage varies by workflow.
- Desktop upgrades, previous-desktop rollback, interrupted-operation recovery
  and configuration backups that preserve later personal edits. GNOME remains
  available as a fallback.
- A read-only physical hardware collector and local acceptance checklist.

## Version policy

The bootstrap and plain desktop upgrade default to `v0.1.0-alpha`. A future
release requires its explicit tag; `OMADORA_REF` and `upgrade --ref` remain
available for deliberate overrides. Omarchy source is pinned to commit
`c668141e9c42b13c80c9ca4ea108e11708c5e8a5`.

This pins Omadora/Omarchy source. Fedora/COPR RPMs, Flatpaks and some optional
workflows still follow their repositories. The complete installed system is
not bit-for-bit reproducible, and this is not a signed Omadora RPM channel.

## Verified evidence

- [Fresh official Fedora Workstation ISO installation and 15 acceptance checks](https://github.com/DanielCoffey1/omadora/actions/runs/35363116387)
  at `b76f862`: UEFI/Btrfs disk boot, SELinux enforcing, public Omadora
  bootstrap/reboot, desktop interaction, password login after upgrade/rollback,
  clipboard, scaling, themes, portals, network/audio and GNOME/config recovery.
  Initial login uses test autologin; the test account is provisioned after
  Anaconda, so GNOME's first-run account wizard is outside this coverage.
- [42 source checks and Linux hardware-collector smoke test](https://github.com/DanielCoffey1/omadora/actions/runs/35369080168)
  at `694e1bb`; the collector correctly labels hardware checks NOT TESTED.
- [Codex CLI and Claude Code Fedora runtime tests](https://github.com/DanielCoffey1/omadora/actions/runs/35301839112):
  installation, version/help, launcher validation, removal and profile
  preservation. No account or model request was tested.
- The project owner reports that Omadora worked on their laptop. Hardware
  model, drivers and individual checklist results were not supplied; this is
  user-reported feedback, not a completed hardware certification matrix.

The linked runs identify the revisions actually tested. The alpha adds release
version metadata and pinned default references; it does not represent a fresh
ISO rerun at the release tag. Detailed history and application scopes are in
[validation](https://github.com/DanielCoffey1/omadora/blob/v0.1.0-alpha/docs/VALIDATION.md)
and [app results](https://github.com/DanielCoffey1/omadora/blob/v0.1.0-alpha/docs/APP_TESTS.md).

## Known limitations

- This is not complete 1:1 Omarchy parity or a stable release. Optional menu
  mappings do not establish end-to-end operation of all 93 app workloads.
- Physical GPU, Wi-Fi/Bluetooth, multiple-monitor and suspend coverage remains
  incomplete. NVIDIA driver installation and Secure Boot support are not
  established. Encrypted-disk installation was not covered by the ISO VM run.
- QEMU/virtio suspend/resume still fails. A single Bochs virtual display passed
  three cycles; that workaround is not a physical GPU fix.
- Full application theme parity, accounts, gameplay, interactive container/VM
  workloads and several device-specific features remain unverified.
- No full uninstall, OS rollback, automatic incompatible config migration or
  versioned Omadora RPM repository. Recovery retains package/repository changes.
- Other Fedora releases/spins, Atomic desktops, ARM and existing heavily
  customized desktop setups are outside this initial target.
