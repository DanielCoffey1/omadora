# Omadora v0.2.1-alpha

Application discovery refreshes after catalog/package installs and removals,
web-app/TUI changes, and each time the launcher opens. A fresh Gio desktop-entry
snapshot updates the existing searchable Apps menu without restarting the shell.
This avoids relying solely on delayed or missed file notifications. Flatpak
export paths are included even when first created during the current session.
The existing theme, sorting and search remain unchanged.

Target: Fedora Workstation 44, x86_64, non-Atomic. Includes all v0.2.0-alpha fixes.

## Install

```bash
curl -fsSL https://raw.githubusercontent.com/DanielCoffey1/omadora/v0.2.1-alpha/boot.sh | bash
```

Existing users: log out of Hyprland and run from GNOME or a TTY:

```bash
omadora upgrade --ref v0.2.1-alpha
```

No theme reset is needed. Shell refresh is best effort when no desktop is
running, and cannot turn a successful package installation into a failure.
Apps must provide a visible desktop entry; command-line-only packages are not
automatically given a launcher entry.

The Fedora integration test exercises the actual patched Quickshell app library
and Gio scanner: late-created local and Flatpak directories, additions, in-place
edits, hidden entries and removal must update within five seconds without a
shell restart. This is a headless test; it does not certify a latency bound on
all physical hardware. Existing alpha hardware/workload limitations remain in
[the validation record](../VALIDATION.md).
